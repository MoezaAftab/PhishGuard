## 1. What is PhishGuard?

Phishing is the #1 cyber attack in the world. Criminals send deceptive emails, text messages, or websites pretending to be trusted companies (like PayPal, Google, Apple, or your bank) to trick you into entering your password or credit card details.

Traditional antivirus programs only look at a simple blocklist of known bad websites. But hackers create thousands of brand new websites every day that aren't on any blocklist yet!

**PhishGuard** solves this problem by using an **autonomous Multi-Agent Architecture**. Instead of relying on one single checklist, PhishGuard deploys **5 specialized software "agents" (detectives)** that inspect the target from different angles simultaneously and vote on whether it is safe or malicious.

## 2. The Real-World Analogy: The 5-Detective Cyber Squad

Imagine a detective agency investigating a suspicious letter. Instead of one person guessing, you hire a team of 5 specialized investigators:


### 🕵️ Detective 1: URL Security Inspector (`agents/url_agent.py`)
- **Job:** Inspects the website address (URL) character-by-character.
- **What it looks for:**
  - **Typosquatting:** Is the domain `paypa1.com` instead of `paypal.com` (using the number `1` instead of the letter `l`)?
  - **Randomness (Entropy):** Does the address look like `x8k2-m9zq.xyz` generated by a bot?
  - **Raw IP hosts:** Is the link `http://192.168.1.50` instead of a real company domain?
  - **Sneaky TLDs:** Is it using high-abuse domain extensions like `.xyz`, `.top`, `.click`?

### 🧠 Detective 2: Social Engineering & Content Analyst (`agents/content_agent.py`)
- **Job:** Reads the text of the email or webpage to understand psychological manipulation.
- **What it looks for:**
  - **Artificial Urgency & Panic:** Words like *"Your account will be PERMANENTLY DELETED in 24 hours!"*
  - **Credential Traps:** Prompts asking you to *"Confirm your password"*, *"Enter your SSN"*, or *"Update credit card"*.
  - **Link Mismatches:** Does the visible text say `https://chase.com`, but when you hover over it, the link secretly takes you to `http://evil-steal-password.com`?

### 📬 Detective 3: Header & Authentication Verifier (`agents/header_agent.py`)
- **Job:** Inspects the technical "postal stamps" of the email.
- **What it looks for:**
  - **SPF (Sender Policy Framework):** Did the sending computer have legal permission from the domain owner to send this email?
  - **DKIM (DomainKeys Identified Mail):** Was the email cryptographically signed by the genuine sender, or was it tampered with in transit?
  - **DMARC:** Does the email match official company policies?
  - **From vs. Reply-To Mismatch:** If the email claims to come from `support@apple.com`, but replies are secretly routed to `scammer@inbox.ru`?

### 🌐 Detective 4: Threat Intelligence & DNS Verifier (`agents/threat_intel_agent.py`)
- **Job:** Performs real-time internet background checks on the domain.
- **What it looks for:**
  - **DNS MX Records:** Does the sender's domain even have an email server configured? Burner phishing domains often forget to set up MX records!
  - **Dynamic DNS & Tunneling:** Is the site hosted on free dynamic tunnels like `duckdns.org` or `ngrok.io`?
  - **SSRF / Private IP Traps:** Does the link secretly try to query internal home router or cloud server addresses (`127.0.0.1`, `169.254.169.254`)?
  - **External Threat Feeds:** Queries VirusTotal if an API key is provided.

### 📊 Detective 5: Explainable ML Classifier (`agents/ml_agent.py`)
- **Job:** Converts all structural, linguistic, and behavioral clues into a statistical risk formula.
- **What it looks for:**
  - Computes weighted feature impact scores.
  - **Explainability:** It doesn't just say "danger" — it gives you a transparent breakdown: *"Aggressive Caps (+12 pts), Credential Harvesting (+22 pts), Typosquatting (+20 pts)"*.

### 🎖️ The Chief Detective: The Orchestrator (`agents/orchestrator.py`)
- Listens to all 5 detectives.
- Weights their opinions fairly.
- Enforces the **Critical Escalation Rule**: If even one agent finds definitive proof of malicious spoofing (score > 85), the overall verdict cannot be watered down to "safe".
- Produces a clear 0 to 100 risk score and step-by-step mitigation advice for the user.

## 3. Python 101: Understanding the Language Through This Project

If you haven't written Python before, don't worry! Python is famous for reading almost like plain English. Here are the core concepts used in PhishGuard:

### A. Variables (Boxes that store data)
```python
score = 85.5                       # A decimal number (Float)
verdict = "CRITICAL"               # Plain text (String)
is_phishing = True                 # A yes/no switch (Boolean)
target_brands = ["paypal", "apple"]# A list of items (List)
```

### B. Dictionaries (Key-Value pairs, like a contact card)
```python
user_input = {
    "url": "http://paypa1.xyz/login",
    "subject": "Urgent Security Alert"
}
# Accessing data:
print(user_input["url"])  # Prints: http://paypa1.xyz/login
```

### C. Functions (Reusable recipes of code)
A function takes inputs (arguments), does work, and gives back an answer (`return`):
```python
def check_score(score):
    if score >= 85:
        return "CRITICAL"
    elif score >= 50:
        return "SUSPICIOUS"
    else:
        return "SAFE"
```

### D. Classes and Inheritance (Blueprints and Specialists)
In PhishGuard, every agent follows the same standard contract. We defined a parent blueprint called `BaseAgent`:
```python
class BaseAgent:
    def __init__(self, name, weight):
        self.name = name
        self.weight = weight

    def analyze(self, data):
        pass  # Each specific agent fills in its own custom logic!
```
Then, `UrlAgent` inherits from `BaseAgent`:
```python
class UrlAgent(BaseAgent):
    def __init__(self):
        super().__init__(name="URL Security Inspector", weight=1.2)
    
    def analyze(self, data):
        # Specific URL inspection code lives here!
```

### E. Decorators (The `@` symbols before functions)
In `app.py`, you will see:
```python
@app.route("/")
def index():
    return render_template("index.html")
```
The `@app.route("/")` decorator tells Flask: *"Whenever someone opens the homepage in their web browser, run this `index()` function!"*

## 5. The Life of a Scan: Step-by-Step Code Flow

What actually happens when a user types a link into the browser and clicks **"Inspect URL Threat Level"**?

```
[1. User's Browser]
        │ Types "http://paypa1.xyz/login" & clicks Submit
        ▼
[2. Flask Web Server (app.py)]
        │ Checks CSRF Session Token (Stops fake cross-site requests)
        │ Checks Rate Limiter (Flask-Limiter)
        │ Sanitizes input (security.py: checks for dangerous "javascript:" or SSRF)
        ▼
[3. PhishGuard Orchestrator (orchestrator.py)]
        │ Generates unique Scan ID (e.g., "a8f3b190")
        │ Fans out data to the 5 Autonomous Agents
        ├──► UrlAgent: Calculates typosquatting & entropy
        ├──► ContentAgent: Checks for credential harvesting prompts
        ├──► HeaderAgent: Checks for sender alignment
        ├──► ThreatIntelAgent: Checks DNS A/MX records & dynamic DNS
        └──► MLAgent: Computes weighted statistical probability
        ▼
[4. Ensemble Consensus Engine]
        │ Calculates weighted average
        │ Checks Critical Escalation Rules
        │ Formulates tailored mitigation recommendations
        ▼
[5. Database Layer (database.py)]
        │ Saves full JSON report to Supabase Cloud
        │ (or seamlessly saves to local SQLite if offline)
        ▼
[6. Jinja2 Template (templates/report.html)]
        │ Combines data with HTML, CSS & cyber visual gauges
        ▼
[7. User's Browser]
        Displays interactive threat assessment, risk gauge, and findings!
```

## 6. Cybersecurity & Penetration Testing: How We Secured the App

Building a cybersecurity app means our own website must be bulletproof against attackers. We implemented comprehensive defensive security and built an automated **Security Audit Test Suite (`tests/test_security_audit.py`)**:

### 1. Cross-Site Scripting (XSS) Defense
- **The Threat:** A hacker types `<script>alert('pwned')</script>` into the email subject to steal session cookies.
- **Our Defense:** Jinja2 templates auto-escape all dynamic data (turning `<` into `&lt;`). Furthermore, our `security.py` validates text inputs.

### 2. Server-Side Request Forgery (SSRF) Defense
- **The Threat:** An attacker submits `http://169.254.169.254/latest/meta-data/` to trick our server into revealing cloud credentials.
- **Our Defense:** `security.py` checks target hostnames against `PRIVATE_NETWORKS` and cloud metadata IP ranges, rejecting loopback targets immediately.

### 3. SQL Injection (SQLi) Defense
- **The Threat:** An attacker types `' OR '1'='1` into the search bar to dump the whole database.
- **Our Defense:** We never concatenate raw text into SQL strings. We use **parameterized queries (`?`)** in SQLite and PostgREST ORM in Supabase, making SQL injection mathematically impossible.

### 4. Cross-Site Request Forgery (CSRF) Defense
- **The Threat:** A malicious website submits unauthorized scan requests on behalf of an authenticated user.
- **Our Defense:** Cryptographically random session tokens (`secrets.token_hex(32)`) verify that forms were genuinely submitted from our own web page.

### 5. Rate Limiting & Denial of Service (DoS) Defense
- **The Threat:** A bot spams 10,000 requests per second to crash the server.
- **Our Defense:** `Flask-Limiter` enforces strict limits (e.g. max 30 scans per minute per IP address). Oversized payloads (> 5MB) are dropped immediately.

### 6. Modern HTTP Security Headers
Every HTTP response sent by PhishGuard includes OWASP-recommended headers:
- `Content-Security-Policy`: Blocks unauthorized script execution.
- `X-Frame-Options: DENY`: Prevents clickjacking (framing inside malicious iframes).
- `X-Content-Type-Options: nosniff`: Prevents MIME-confusion attacks.
- `Referrer-Policy: strict-origin-when-cross-origin`: Protects user privacy.

## 7. The Database: Supabase Cloud & Local SQLite Fallback

PhishGuard features a **dual-engine database architecture** in `database.py`:

```
                    ┌─────────────────────────┐
                    │      database.py        │
                    └────────────┬────────────┘
                                 │
             ┌───────────────────┴───────────────────┐
             ▼                                       ▼
  [SUPABASE CLOUD ACTIVE?]                    [OFFLINE / NO KEYS]
             │                                       │
     ✅ YES  │                               ❌ NO   │
             ▼                                       ▼
 ┌───────────────────────┐               ┌───────────────────────┐
 │ Supabase Cloud Hosted │               │  Local SQLite File    │
 │ PostgreSQL Database   │               │   (phishguard.db)     │
 └───────────────────────┘               └───────────────────────┘
```

### How to Connect Supabase Cloud in 3 Minutes:
1. Go to [supabase.com](https://supabase.com) and create a free account.
2. Click **"New Project"** and give it a name (e.g. `phishguard-db`).
3. In the left sidebar, click **SQL Editor**.
4. Open the file [`schema.sql`](file:///c:/Users/User/Desktop/PhishGuard/schema.sql) in this project, copy its contents, paste it into Supabase, and click **Run**.
5. In Supabase, go to **Project Settings -> API** and copy:
   - **Project URL**
   - **anon / public key**
6. Open `.env` (or copy `.env.example` to `.env`) in PhishGuard and fill them in:
   ```env
   SUPABASE_URL=https://your-project-id.supabase.co
   SUPABASE_KEY=your-actual-supabase-anon-key
   ```
7. Restart the app! The navbar will automatically display **`DB: Supabase Cloud`**. All scans will now be synced in real-time to your cloud PostgreSQL database.

## 8. The REST APIs Explained

PhishGuard is not just a website; it is also a complete security API platform. Developers and security operations centers (SOCs) can integrate with it programmatically.

Open your browser to **`http://localhost:5000/api-docs`** for interactive documentation.

### API Endpoints Summary:
- `POST /api/v1/scan`: Full 5-agent scan across URL, content, or email headers.
- `POST /api/v1/agents/url`: Directly invoke Agent 1 (URL Inspector).
- `POST /api/v1/agents/content`: Directly invoke Agent 2 (Social Engineering Analyst).
- `POST /api/v1/agents/header`: Directly invoke Agent 3 (Header Verifier).
- `POST /api/v1/agents/threat-intel`: Directly invoke Agent 4 (Threat Intel & DNS).
- `POST /api/v1/agents/ml`: Directly invoke Agent 5 (ML Classifier).
- `GET /api/v1/scans`: Retrieve historical scan reports from the database.
- `GET /api/v1/scans/<id>`: Retrieve a specific scan report by ID.
- `GET /api/v1/stats`: Retrieve aggregate threat statistics.
- `GET /api/v1/health`: Server health and active agent statuses.

## 9. How to Deploy to Vercel or Render in 5 Minutes

### Option A: Deploy to Vercel (Serverless Cloud)
We have already configured [`vercel.json`](file:///c:/Users/User/Desktop/PhishGuard/vercel.json) and [`api/index.py`](file:///c:/Users/User/Desktop/PhishGuard/api/index.py).

1. Push this folder to a GitHub repository:
   ```bash
   git add .
   git commit -m "Complete PhishGuard platform"
   git push origin main
   ```
2. Log in to [vercel.com](https://vercel.com).
3. Click **"Add New Project"** and select your GitHub repository.
4. Under **Environment Variables**, add:
   - `SECRET_KEY`: `your-random-secret-key`
   - `SUPABASE_URL`: `https://your-project.supabase.co`
   - `SUPABASE_KEY`: `your-supabase-anon-key`
5. Click **Deploy**! Vercel will build and host your app on a free global URL (e.g. `https://phishguard.vercel.app`).

### Option B: Deploy to Render (Long-Running Container)
We have already included [`Procfile`](file:///c:/Users/User/Desktop/PhishGuard/Procfile) and [`wsgi.py`](file:///c:/Users/User/Desktop/PhishGuard/wsgi.py).

1. Go to [render.com](https://render.com) and click **"New Web Service"**.
2. Connect your GitHub repository.
3. Set **Build Command**: `pip install -r requirements.txt`
4. Set **Start Command**: `gunicorn wsgi:app`
5. Add your environment variables and click **Create Web Service**.
